# Astra Eco Eval

評価を依頼されたときだけ動く。常駐監視、定期LLM呼び出し、追加の評価エージェント、タスクの自動再実行をしない。

1. ユーザーが指定した記録の範囲だけ扱う。全セッションを探索・読み込みしない。記録がなければ [measurement.md](references/measurement.md) の形式を示し、計測方法を整える。欠測を推測で埋めない。
2. `scripts/summarize.py records.jsonl` で決定的に集計する。Python標準ライブラリのみを使い、APIを呼ばない。
3. 最初に集計結果だけ読む。詳細確認が必要なら、判断を変え得る事例を最大2件選ぶ。ユーザーが深い調査を求めた場合はその範囲に合わせる。
4. 合格率、欠測、使用量、時間を確認する。群ごとの集計は記述統計であり、タスク難度や選択偏りを除去していない。通常運用の観測だけで因果的な削減率を報告しない。
5. 「観測事実／不明点／改善候補最大1件／次の確認」を短く返す。新しい証拠がなければ変更不要とする。文章が似ているだけでツール呼び出しを無駄と判定しない。

スキルの自動書き換え・公開はしない。改善実装を依頼された場合は1つの仮説に絞り、旧版をGitで保持し、合格条件を維持して評価する。悪化または効果不明なら採用を見送る。比較のための有料実行を勝手に追加しない。

評価自身の使用量も別の `evaluation` 記録として残せる。取得できなければ不明とする。評価費用を成果側の削減から隠さない。削減額が未確定なら「評価費用を回収した」と表現しない。
